# Clock clone across iOS 16 and 17

For the v0.1.9 baseline, the independent UIKit project [`ClockCurrentAutoProbe`](../rebuild/ClockCurrentAutoProbe) was built from the same source. Its ad hoc IPA's executable SHA-256 (`06282bd9234b2a9883ba51e21f357c79f90d521a05351a1590e3d4c5d8b5562e`) matches the executable in the previously installed XR IPA. A copy of that build was development-signed for the iPhone 14; signing changes the Mach-O signature bytes. The signed IPA SHA-256 is `76c0a138b80e1a3f3b060ce0a6953d7fba801c536345c9ecc13b310bce99b362`. The iOS 17 USB installation case `cases/ios17-clock-auto-install-20261017/` confirms Bundle ID `com.copyapp.clock.currentauto`, version 0.1.0 (1), and a valid installed profile.

The same committed [original](../playbooks/clock-paired-stopwatch-original.json) and [clone](../playbooks/clock-paired-stopwatch-clone.json) scripts selected Stopwatch, started it, observed a nonzero running state, stopped it, and captured a stable stopped screen. Original and clone passed separate iOS MCP captures and `compare-playbooks` on **each** phone:

| Phone | Paired evidence | Additional clone backend |
| --- | --- | --- |
| XR / iOS 16.1.1 / Dopamine rootless | `cases/ios16-clock-paired-fair-{original,clone,compare}-20261017/` | iCTRL: `cases/ios16-clock-clone-ictrl-20261017/` |
| iPhone 14 / iOS 17.3.1 / Relaxin RootHide | `cases/ios17-clock-paired-fair-original-retry-20261017/`, `cases/ios17-clock-paired-fair-{clone,compare}-20261017/` | iCTRL: `cases/ios17-clock-clone-ictrl-20261017/` |

All six final UI capture cases, both comparison cases and the iOS 17 install case passed `copyapp verify`. The side-by-side stopped screens were manually inspected. Both show a running result followed by Reset and Start controls, one lap row, and the Stopwatch tab. The saved screenshots differ in timer value because action and observation latency differs between runs; pixel distance is not a fidelity score. On iOS 17 the original also has a different tab wording (`Alarms`/`Timers` versus `Alarm`/`Timer`), control styling and system return-to-App label. These are visible differences, not exact visual parity.

The original Clock retains the stopped stopwatch value across a fresh launch. The **v0.1.9 baseline clone** started at zero again. A unified pre-run Reset action therefore failed on that build and was removed from the paired script; the original was reset separately with [this preparation script](../playbooks/clock-stopwatch-reset-original.json). A transient iOS 17 SpringBoard foreground race on one original-App run also produced a saved failed case; the next run completed without changing the script. These failures remain local evidence, not passing cases.

## Stopwatch state fix in build 0.1.1 (2)

The current clone saves elapsed time, start timestamp and lap state, then restores them on process launch. The upgraded ad hoc IPA SHA-256 is `6e9e18f68200c3c2412f8817b73afaef8fd87faa85e4511e7c18ec12666876ab`; the development-signed iOS 17 IPA is `9fd19f1dc3cd807e99ebb50cbca6ed1f081e264ef17249e9abfb22e5323efe63`. Both updated install cases verify. The first XR TrollStore upgrade timed out while the old clone was running; after stopping only that process, a new install case passed. The iOS 17 USB upgrade also completed after stopping the old process.

On each phone, a start/stop capture followed by a **fresh process launch** retained the exact stopped stopwatch value: XR `00:02.31`, iPhone 14 `00:01.69`. The clone's stopped relaunch script and the [original script](../playbooks/clock-stopped-relaunch-original.json) passed same-device comparisons with saved side-by-side screenshots. During a separate running-state test, the XR clone advanced from `00:01.25` before relaunch to `00:35.20` and `00:36.84` after relaunch; the iPhone 14 advanced from `00:01.25` to `00:12.99` and `00:14.44`. The running clocks were then stopped. The updated build also passed the standard start/stop script through iCTRL on both phones. Seventeen of the eighteen build-2 cases remain verifiable: the XR build-2 install record pointed to a mutable `build/dist/` IPA that was later overwritten. The original bytes are unavailable, so that one historical install case is no longer counted as verified. Its UI captures and the iOS 17 signed install case still verify.

Build **0.1.2 (3)** packaged the same persistence code for a real upgrade check. With build 2 running on each phone, `copyapp install` requested exact-target termination through paired iCTRL. The XR path additionally checked each matching process's on-device `Info.plist` before stopping it. Both `cases/ios{16,17}-clock-build3-auto-upgrade-20261017/` install cases completed in about seven seconds, verified version/build and package hash, and the build-3 relaunch cases still showed a nonzero stopped stopwatch and Reset. The XR ad hoc IPA SHA-256 is `ed96255dbfb5f7c4279af07230f4fb7db7e8863bed3bd7bc584cc9a7147dbce0`; the iPhone 14 development-signed IPA is `e4b42afd0e13118fa2f1b70491e8217efbc4e95e0ee9bf90c88a744009a6a348`. A separate direct XR probe stopped one running Clock process only after its bundle's `Info.plist` matched the requested Bundle ID. Two attempts to reinstall identical build 2 through TrollStore timed out despite process cleanup; those failed cases remain local and same-version reinstall is not claimed.

For build **0.1.3 (4)**, `install` saves a case-local `input.ipa` before transfer, so later rebuilds cannot overwrite its verification source. The XR ad hoc IPA SHA-256 is `538591251caee5b1fadcefc62cb28f7feea949287b30c8606415322d8d788d42`; the iPhone 14 development-signed IPA is `53f05117f663c6d24d350fad2f195edfac712b8de7ab3cfa9ac9970fd6896811`. Build 4 was installed on both phones from a running build 3; iPhone 14 USB installation passed on its first attempt. The XR TrollStore helper timed out on its first attempt and InstallationProxy still reported build 3, then a retry of the same retained IPA succeeded. Both final install cases contain their own IPA snapshot, pass `copyapp verify` even with the original build output temporarily removed, and the build-4 relaunch captures show nonzero stopped Stopwatch state. The first XR timeout remains a failed case. The earlier XR build-3 IPA was copied byte-for-byte into its local case before rebuilding, with the relocation recorded; that case also continues to verify.

The current project version is **0.1.4 (5)**, with the same Stopwatch code. Its XR ad hoc IPA SHA-256 is `cd403edd08534c1c4049f8320af4bfbc526d7f7c317e92cffee1b12704410ee5`; the iPhone 14 development-signed IPA is `872a603dc411afe72c4b5a4f52619622f8afed76fdf3c54feff49086671ec7b4`. Both versioned upgrades passed on the first attempt. The install cases `cases/ios{16,17}-clock-build5-upgrade-v0111-20261017/` verify, and the post-upgrade relaunch cases retained the exact previously stopped values: XR `02:52.80`, iPhone 14 `02:00.94`. This successful attempt does not erase the earlier XR helper timeouts or establish a first-attempt reliability rate. The separate [one-minute background check](clock-background-two-device.md) was performed on build 4.

This validates selected foreground Stopwatch behavior, stopped-state persistence, and one running-state relaunch per phone. It does not validate long background timing accuracy, wall-clock changes, alarms, notifications, all Clock pages, exact visual parity, arbitrary iOS 16/17 devices or whole-App equivalence. `cases/` is intentionally Git-ignored; rerun the committed scripts and verify the resulting cases on a configured Mac.
