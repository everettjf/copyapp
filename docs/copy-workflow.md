# Copy APP workflow

**Language:** English | [简体中文](copy-workflow.zh-CN.md)

Copy APP treats “analyze” and “rebuild” as one resumable, evidence-gated job for selected behavior on a specified jailbroken iPhone. Its current-device mode is intended for a Codex or Claude Code session already working in this repository. The standalone mode can launch a separate coding-agent CLI. A [Codex CLI XR trial](external-codex-xr-trial.md) completed selected report, build, installation and paired checks using existing discovery scripts and clone source; autonomous discovery and new implementation for an unfamiliar App remain unverified.

The core stages are validated on iPhone XR / iOS 16.1.1 (rootless) and on [iPhone 14 / iOS 17.3.1 (Relaxin/RootHide)](relaxin-roothide-iphone14.md). The earlier iOS 17 run reused an existing clone; a separate [new-source four-flow pilot](ios17-calculator-fresh-from-report.md) validates report-guided implementation and real-device comparison. Fresh v0.1.10 device-channel checks and the exact selected network-observer boundary are in the [two-device matrix](two-device-verification-matrix.md). See the [support table](../README.md) for setup and limits.

The known-source fixture's packaged share extension has also been [opened through the system share sheet on both phones](fixture-share-extension-two-device.md). Its current version reads and displays the exact synthetic plain-text item on both devices; other item types and extensions remain outside this check.

For a new Mac and phone, run `sh scripts/bootstrap-macos.sh`, then `.venv/bin/copyapp onboard --stage rebuild` (add `--udid` when several devices are connected). It saves a device and Mac capability report with ordered repairs. Once the required phone services and pinned SSH key are ready, the analysis and copy workflows open their own exact-device SSH and UI forwards. Keep `.venv/bin/copyapp tunnel --udid <UDID>` open only when doing the one-time host-key check or interactive UI work. SSH host-key fingerprint comparison and phone pairing prompts remain explicit one-time steps.

## 1. Discover representative behavior

```sh
.venv/bin/copyapp copy --udid <UDID> --bundle <ORIGINAL_BUNDLE> \
  --auto-discover --agent-provider current \
  --project rebuild/<NEW_PROJECT> --rebuilt-bundle <NEW_BUNDLE> \
  --out cases/<WORKFLOW>
```

The initial command writes `discovery-agent/TASK.md` and pauses before touching the phone. The current agent observes the actual app, creates 3–12 distinct bounded playbooks under `discovery-agent/candidates/`, and submits them to `copyapp discover-check` using the exact device, Bundle ID and UI backend. That command statically checks identity and action bounds before replay, then saves a verified case at `discovery-agent/discovery/`. Keep failed attempts for diagnosis; inspect phone state before a new attempt. The accepted case pins script bytes, device identity and replay evidence. It establishes only the observed paths, not whole-app coverage.

Each playbook may use bounded taps, swipes, long presses and double taps. Include a post-action state assertion when available; a successful gesture call does not prove the intended UI effect. See the [gesture guide](ui-gesture-playbooks.md) ([中文](ui-gesture-playbooks.zh-CN.md)) for parameters and backend differences.

For input-heavy apps, use [bounded text entry](ui-text-playbooks.md) ([中文](ui-text-playbooks.zh-CN.md)) after focusing an empty field. Check the resulting UI: an input RPC can succeed without visible text reaching the app.

The [Translate XR case](translate-xr-workflow.md) ([中文](translate-xr-workflow.zh-CN.md)) is a concrete three-flow run using iCTRL for visible text input. It reaches a reviewed report, an independently built UIKit app, paired replay and a screenshot-by-screenshot visual review without REA. The example documents the exact behavior covered and the remaining differences.

If a verified discovery case already exists, use `--discovery <CASE>` instead; if scripts were chosen explicitly, use repeated `--script <FILE>`. The three inputs are mutually exclusive.

## 2. Prepare and interpret

Resume the identical `copyapp copy` invocation with `--resume`. The parent verifies discovery and calls `prepare-app`: package and sandbox collection, requested Mach-O recovery, UI/runtime investigation and a semantic review draft. On `analysis_agent_needs_review`, read `analysis-agent/TASK.md` and all linked evidence. Produce a formal report and `feature-spec.json` under `analysis-agent/reviewed-report/`, then run `copyapp analysis-delivery` into `analysis-agent/analysis-delivery/`. The delivery gate checks exact source identity and every selected flow's evidence link. An agent must still judge the meaning of the decompiled functions and state unknown behavior explicitly.

For a package whose indexed Mach-O files are all unencrypted, the requested recovery stage now verifies and records a source snapshot without starting the device decryption helper. The manifest identifies this as `source_snapshot_unencrypted`; it must not be reported as a successful decrypt operation.

Before implementation, turn the reviewed analysis into a [known-capability inventory and milestone target](coverage-targets.md). Choose named end-to-end capabilities, record deferred and blocked ones, and preserve unknown areas. A 50–60% first milestone may be appropriate for a large App; a small App may target all known capabilities. Once `rebuild-plan` exists, run `coverage-plan --report <REPORT> --plan <PLAN> --inventory <JSON> --out <TARGET_CASE>` and verify the target case. It freezes the reviewed denominator and target; it does not make the inventory exhaustive.

By default the native path needs no REA. For direct decompilation, choose `--analysis-provider ghidra-direct --ghidra-dir <DIR> --java-home <JDK_HOME>` or `--analysis-provider hopper-direct` (optionally `--hopper-app <Hopper.app>`). Ghidra needs a JDK; Hopper needs its licensed GUI app in a normal macOS user session. An integrated `investigate-flow --provider hopper-direct` run on the iOS 16.1.1 XR completed UI replay, Frida tracing and Hopper decompilation, and the result was imported into a verified report. A [one-flow iOS 17 Hopper `copy` parent](../cases/ios17-hopper-current-parent-20261017/manifest.json) also completed report, existing-source installation and paired delivery. Runtime method hits and static pseudocode are separate evidence; neither alone proves a full implementation.

## 3. Build and compare

Resume the same command again. `prepare-rebuild` creates a source-linked task and the workflow pauses at `rebuild-agent/TASK.md`. Implement an independent Xcode project at the specified `--project`; install it on the pinned device and save installation evidence. For a development-signed IPA, use `copyapp install --transport usb --udid <UDID> --ipa <IPA> --out <CASE>`; the existing TrollStore path remains the default. Verify the install case, then run `rebuild-task-check` for the selected original and clone playbooks on the same UI backend. Inspect every screenshot pair, save `visual-review`, and run `agent-delivery` **without** `--run` in current-device mode. For a selected flow that changes local data, also capture the indexed sandbox file before and after the action (`copyapp sandbox-file` now owns its exact-device SSH forward), inspect the bounded content locally, and compare it with the original App. A matching UI count alone cannot prove matching stored values; the [v0.1.2 fixture check](development-checkpoints/v0.1.2.md) found and repaired exactly that difference. The completed parent requires behavior or final-view assertions for every selected flow, a review of all captured pairs and no major visual difference. Minor differences must be recorded.

If `rebuild-plan` marks a flow `needs_verified_screenshot`, the cited original playbook has no stable screenshot with a `ready_contains` check. Capture a new original flow with that condition, cite the new evidence in a reviewed report, then regenerate the plan. The plan and agent task remain verifiable and identify the missing evidence; they do not turn an unverified image into a passing paired check.

Declare each script's starting page and first-use state. A fresh launch can restore the last editor or search page, as the [system Notes XR run](notes-xr-workflow.md) demonstrated. When two flows depend on different restored pages, navigate to the expected page, background the App so iOS saves it, retain that setup evidence, and resume the same failed check. Do not reinterpret an onboarding overlay or changed fixture count as a core behavior match.

A final `--resume` marks the parent complete only if all child cases and source links verify. `copyapp verify cases/<WORKFLOW>` rechecks recorded hashes; it does not certify semantic correctness or behavior outside the selected flows. Do not launch `copyapp agent-run` or another Codex/Claude process from an active coding-agent session.

At delivery, keep selected-flow pass counts separate from the inventory target. After `agent-delivery`, run `coverage-delivery --plan <TARGET_CASE> --delivery <DELIVERY_CASE> --review <JSON> --out <COVERAGE_CASE>` and verify it. Report the original target, any dated scope revision, verified known coverage when the denominator is defensible, unverified selected items, deferred/blocked items and unknown areas. Major visual or server-behavior gaps remain explicit even if the runnable clone passes its other selected checks. The coverage verifier checks source identity, selected-flow gates and arithmetic; a reviewer remains responsible for inventory completeness and semantic judgments.

## Current validation boundary

The iPhone XR on iOS 16.1.1 has completed a three-flow Clock current-agent parent workflow, including report, independent app source, install, 3/3 behavior and terminal-view assertions, and 10 reviewed screenshot pairs with minor differences. A separate [Clock auto-discovery parent](../cases/clock-current-auto-workflow-20261016/manifest.json) completes those gates after replaying three previously authored scripts and adapting prior independent source. The [fresh Calculator parent](../cases/calculator-current-auto-workflow-20261016/manifest.json) adds agent-authored scripts from the current XR UI and a new UIKit project. Its three selected arithmetic flows passed paired behavior and terminal-view assertions, with three image pairs reviewed as minor differences and none major; the parent and delivery verify. An external-process discovery trial used fixed scripts. General discovery across unfamiliar apps, a real autonomous external CLI run and whole-app equivalence remain unverified. The iPhone 14/iOS 17.3.1 has completed USB and SSH acquisition, a verified development-signed clone installation, paired arithmetic flows through both iOS MCP and iCTRL, and one encrypted App plus extension recovery. Original Calculator Frida tracing and a five-tap method-bound flow pass through the pinned 17.23.3 RootHide sidecar; the packaged 16.1.4 server still fails on that App. A [reviewed deep report](../cases/iphone14-calculator-frida17-deep-report-v3-20261017/report.md), report-derived task, paired final-view assertion (`15`), two reviewed screenshot pairs and [selected-flow delivery](../cases/iphone14-calculator-frida17-agent-delivery-20261017/report.md) verify. That delivery reused older source and IPA; a separate [report-guided new-source pilot](ios17-calculator-fresh-from-report.md) now covers its report-selected flow plus three UI-observed arithmetic flows on the same phone. The iPhone 11/iOS 26.0.1 has passed USB/SSH acquisition, iCTRL, iOS MCP UI service, Frida attach, a reviewed Calculator report and one same-device original/rebuilt arithmetic check. After adapting the independent source to the observed iOS 26 layout, its final saved visual review marks only minor differences; the iOS MCP screenshot path can be black after a fresh launch, so the paired check uses iCTRL.

The later [four-flow iOS 17 parent](../cases/ios17-calculator-current-parent-20261017/manifest.json) joins acquisition, reviewed report, signed independent App and 4/4 same-device final-view checks. A separate [one-flow Hopper-provider parent](../cases/ios17-hopper-current-parent-20261017/manifest.json) now verifies optional direct decompilation through the same handoff. Both use source authored before their parent run. The [two-device matrix](two-device-verification-matrix.md) records matching gesture and synthetic text playbooks through both UI backends on each phone.
