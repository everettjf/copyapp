# Copy APP v0.1.0: two-device release validation

[English](v0.1.0.md) · [简体中文](v0.1.0.zh-CN.md)

This first version supports an evidence-backed **selected-flow** analysis and rebuild workflow. It does not claim to recover original source or reproduce every behavior of an arbitrary App. The device evidence below was collected on 2026-10-17; raw packages, screenshots, sandbox files and pairing material remain in local, Git-ignored `cases/`.

To use this exact version, clone the repository, run `git checkout v0.1.0`, then follow [the Mac setup](../../README.md#install-and-run-your-first-survey). The wheel built for this tag is `copyapp-0.1.0-py3-none-any.whl`; installing it does not install the phone tweak or signing tools.

The formal fixture cases are `ios16-fixture-release-rebuild-check-20261017` and `ios17-fixture-release-rebuild-check-v2-20261017`; their five-image reviews are `ios16-fixture-release-visual-review-20261017` and `ios17-fixture-release-visual-review-v2-20261017`. Each case passed `copyapp verify`. The original fixture uses SwiftUI/UserDefaults, UIKit/SQLite, and a separate Catalog framework; its share extension was packaged and indexed, but its user-facing invocation was not tested. The selected assertions show counts increasing by one and the two local Catalog entries appearing. A visible count alone does not inspect SQLite row contents in this release run.

The final fixture source adds `CFBundleDisplayName` to its share extension and `UILaunchScreen` to its main App. iOS 17 rejected the first package without the extension display name. Without the launch-screen entry, iOS 17 letterboxed the App and iOS MCP's returned point coordinates missed the buttons. Both changes were rebuilt and checked on device. The corrected iOS 16 package was also installed after the formal paired check and passed a fresh counter replay; package acquisition confirmed both metadata entries in the installed App.

## Setup for these two phones

Start with [the Mac setup](../../README.md#install-and-run-your-first-survey), then run `copyapp devices` and use the exact `--udid` for every device operation. When both phones are connected, keep a separate pinned SSH host-key file and a distinct forwarded SSH port per phone. The first simultaneous-device doctor run exposed a shared-host-key mismatch; Copy APP now reports it as such instead of suggesting that OpenSSH is missing. Confirm a new fingerprint against the exact USB device before pinning it. `doctor` and the analysis commands can own temporary exact-device forwards; the TrollStore `install` path needs an active SSH forward on its selected port.

On RootHide, the verified encrypted-package route runs the bounded helper through mobile SSH. Its packaged Frida 16.1.4 server does not attach to the tested Calculator; the separate 17.23.3 sidecar does. The installed server also cannot provide root `root-run`. See the [iPhone 14 record](../relaxin-roothide-iphone14.md) for setup and evidence.

## Release gates and limits

- All 308 local unit tests passed. The suite needs loopback socket access for its iOS MCP mock server.
- Both formal three-flow checks, both visual reviews, the final XR and iOS 17 installs, and both final fixture acquisitions passed `copyapp verify`.
- The XR iOS MCP fresh-launch fallback once retained the previous navigation page; the failed case was saved. Returning to the fixture home page allowed the next observation to pass, and the formal XR check used iCTRL's verified terminate/relaunch path. A fresh launch should still be checked against the expected entry screen.
- An iOS 17 update attempt stalled while the original fixture was running. After iCTRL terminated that App, the same signed IPA installed through USB and its install case verified. Close a running target before replacing its development-signed IPA; preserve an interrupted install case and use a new output directory for the retry.
- iOS 26, arbitrary jailbreak builds, complete App equivalence, unseen server behavior, and automatic implementation of an unfamiliar App without agent review remain unverified.

The checkout and Python wheel are the portable release artifacts. Phone packages need the matching jailbreak toolchain or Apple Development signing for the target phone; build them from this source with the documented setup. The test IPAs and device evidence are intentionally not published.
