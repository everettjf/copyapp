# Copy APP v0.1.7：双机界面补验与 Hopper 校验修复

[English](v0.1.7.md) · [简体中文](v0.1.7.zh-CN.md)

这个修订版修复了 iPhone 14 / iOS 17.3.1 上运行 `copy --analysis-provider hopper-direct` 时发现的真实校验问题。调查和 Hopper 反编译都已完成，但 `app_preparation` 校验器漏认 CLI 支持的 `hopper-direct` 字符串，导致父案例停在 `preparation_incomplete`。现在校验器接受该值，并增加回归测试。恢复**同一份**父案例时复用了已完成的手机调查，随后生成审阅报告、安装已有独立 Calculator App、通过选定的末端 `15` 断言，并将两对截图审阅为轻微差异。[父案例及交付](../../cases/ios17-hopper-current-parent-20261017/manifest.json)通过 `copyapp verify`。复刻源码早于本轮运行。

[双机验证矩阵](../two-device-verification-matrix.zh-CN.md)新增两份已提交的合成脚本，在 iPhone XR / iOS 16.1.1 和 iPhone 14 / iOS 17.3.1 上都分别经 **iOS MCP 与 iCTRL** 重放。Calculator 的竖屏左滑在四种组合中都可见地把 `98 → 9`，并保存前后截图及末端 UIKit 文字；Safari 地址栏在四种组合中都可见地收到精确合成字符串 `copyapp-fixture-hello`，没有提交搜索。八份 `flow-capture` 案例通过 `copyapp verify`。Safari 对照缩小了 XR 上的旧结论：iOS MCP 在 Translate 输入框失败，却能在同一 XR 的 Safari 输入；Translate 失败仍未解决，不能推广为整机故障。

另一份[直连 Hopper 队列](../../cases/ios17-calculator-hopper-queue-20261017/manifest.json)及[补充报告](../../cases/ios17-calculator-hopper-supplement-20261017/report/report.md)也将 Calculator 已跟踪的 `buttonPressed:` 入口与有界伪代码绑定。它解释输入分发结构，不是 Apple 原始源码，也没有恢复私有算术算法。

此前的 [v0.1.6 发布](v0.1.6.zh-CN.md)仍是两机新能力检查和 iOS 17 Calculator 四流程工作流的基线。本版仍不证明整 App 等价、陌生 App 零样本生成、独立 Claude CLI 运行或 iOS 26 支持。

发布验收：**310 项单元测试通过**。已核对 `copyapp-0.1.7-py3-none-any.whl` 元数据和 `copyapp` 命令入口；SHA-256：`495acce37060afa9083ad4f3e60911f61d5c078e93fd6db83d5c425f72263388`。
