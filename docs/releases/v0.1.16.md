# Copy APP v0.1.16: system Notes selected-flow run

[English](v0.1.16.md) · [简体中文](v0.1.16.zh-CN.md)

This release completes one end-to-end system Notes study on a jailbroken iPhone XR / iOS 16.1.1. Copy APP discovered three local-account flows, acquired the installed package, recorded bounded Frida calls, generated exact-binary Hopper evidence, produced a reviewed report, built and installed an independent [UIKit clone](../../rebuild/NotesClone/README.md), and completed three original/clone playbook comparisons. All three screenshot pairs were reviewed with minor differences. The [study](../notes-xr-workflow.md) records the exact scope and remaining gaps.

The run exposed a decryption-stage bug: system Notes' indexed Mach-O files were already unencrypted, yet the default path still launched a device helper and timed out. The decryption stage now verifies the exact-device source snapshot and skips the helper for an unencrypted package. Its recovery manifest and `copyapp verify` distinguish this path from an actual encrypted-package recovery. Existing encrypted-package behavior remains covered by regression tests.

The original App's navigation restoration affected the search script after creating a note. The run saved explicit UI state preparation and resumed the same paired check. A first-run Tags tip was dismissed before final screenshot review. Those are case setup requirements, not evidence that fresh launch resets navigation. The clone covers local folder navigation, plain-text entry with its own JSON persistence, and text search. It does not cover iCloud, rich text, attachments, sharing, locked notes, all system Notes internals, or iOS 17 original Notes.

QA: **322 Python tests passed**; the parent Notes case and component report, install, paired check, visual review and delivery cases passed `copyapp verify`. The wheel was installed into an isolated `/tmp` target, imported as version 0.1.16 and used to verify the parent case.
