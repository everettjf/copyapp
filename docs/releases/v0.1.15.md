# Copy APP v0.1.15: installed-wheel checkout discovery

[English](v0.1.15.md) · [简体中文](v0.1.15.zh-CN.md)

The published v0.1.14 wheel passed its Python checks but looked for optional iCTRL pairing configuration inside site-packages. A source checkout run found the same paired devices. v0.1.15 adds `COPYAPP_SOURCE_ROOT` for wheel users to point at their Copy APP checkout; iCTRL, RootHide Frida configuration, OCR and other Mac helper paths use that checkout. Editable installs continue to use their containing checkout. An invalid explicit path fails with a clear error. The wheel still ships the Python CLI only, so optional source tools require a checkout.

An isolated `/tmp` wheel install with `COPYAPP_SOURCE_ROOT` set passed `doctor` and the same nine-step original Calculator iCTRL playbook on iPhone XR / iOS 16.1.1 and iPhone 14 / iOS 17.3.1. Both playbooks recorded a final accessibility result of `15` after `7 + 8` and passed `copyapp verify`. The two candidate-wheel doctors found SSH, Frida, iOS MCP, screenshots and iCTRL available on both devices. The iOS 17 developer file service also worked. XR developer file listing returned `ConnectionTerminatedError` even after its developer image was remounted; a deviceservice restart attempt timed out. This remains an open device-channel issue, not evidence of a package acquisition failure through SSH.

Release QA: **321 unit tests passed** including the loopback HTTP fixture. Device cases and credentials remain in ignored `cases/`; neither phone IPA nor private data is in the wheel. This patch does not establish fresh-machine setup without manual signing/pairing, arbitrary-App reconstruction, long-run device reliability or iOS 26 support.
