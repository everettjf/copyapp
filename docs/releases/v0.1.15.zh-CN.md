# Copy APP v0.1.15：独立安装 wheel 的源码目录定位

[English](v0.1.15.md) · [简体中文](v0.1.15.zh-CN.md)

已发布 v0.1.14 wheel 的 Python 检查通过，但会错误地在 site-packages 查找可选 iCTRL 配对配置；从源码目录运行时能找到同一批已配对设备。v0.1.15 为 wheel 用户增加 `COPYAPP_SOURCE_ROOT`，指向 Copy APP 源码目录。iCTRL、RootHide Frida 配置、OCR 等 Mac 辅助文件从该目录查找；可编辑安装仍默认使用自身所在源码目录。显式指定无效路径会清楚报错。wheel 仍只包含 Python CLI，使用可选源码工具时需要保留仓库。

从独立 `/tmp` wheel 安装、设置 `COPYAPP_SOURCE_ROOT` 后，iPhone XR / iOS 16.1.1 与 iPhone 14 / iOS 17.3.1 的 `doctor` 和同一条九步原版 Calculator iCTRL 脚本通过。两机都记录了 `7 + 8` 后的辅助功能结果 `15`，脚本均通过 `copyapp verify`。候选 wheel 的两机检查确认 SSH、Frida、iOS MCP、截图和 iCTRL 可用；iOS 17 开发者文件服务也可用。XR 开发者文件列表在重挂开发者镜像后仍返回 `ConnectionTerminatedError`；重启 deviceservice 的尝试超时。这是一项仍未解决的设备通道问题，不表示经 SSH 的包采集失败。

发布验收：**321 项单测通过**，含回环 HTTP 夹具。设备案例和凭据保存在 Git 忽略的 `cases/`；wheel 不含手机 IPA 或私有数据。此补丁不证明全新 Mac 上无人工签名配对的安装、任意 App 复刻、设备长期可靠性或 iOS 26 支持。
