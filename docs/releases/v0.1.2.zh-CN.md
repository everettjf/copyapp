# Copy APP v0.1.2：iOS 16 与 17 的夹具存储核验

[English](v0.1.2.md) · [简体中文](v0.1.2.zh-CN.md)

此版本延续 [v0.1.1 双机验收](v0.1.1.zh-CN.md)。克隆仓库并检出 `v0.1.2` 后，按 [Mac 安装步骤](../../README.zh-CN.md#新用户安装与第一次运行)配置。在 iPhone XR / iOS 16.1.1 / Dopamine rootless 和 iPhone 14 / iOS 17.3.1 / Relaxin RootHide 上，已验证的是**选定流程**的分析与复刻。设备通道、包采集、Frida 和逐图审阅的详细证据见前版记录。

## 深入核验发现的问题

此前 Notes 脚本只断言界面计数加一。直接只读对照 SQLite 后发现：原版写入 `Sample note <Unix 时间戳>`，独立复刻版却只写入 `Sample note`。原有界面和截图检查没有发现这处行为差异。首次采集的本地案例 `ios16-fixtureclone-notes-before/after-20261017` 与 `ios17-fixtureclone-notes-before/after-20261017` 保留了差异证据。

复刻版 `NoteStore` 已改为写入相同格式，重新构建为 0.1.1（build 2），经 XR 的 TrollStore 与 iPhone 14 的 Apple Development 签名 USB 路径分别安装；两个安装案例通过 `copyapp verify`。修复后的同机检查如下：

| 设备 | 原版 Notes 数据库／界面 | 修复后复刻版 Notes 数据库／界面 | 复刻版界面回归 |
| --- | --- | --- | --- |
| XR / iOS 16.1.1 | 14 → 15 行，界面计数一致 | 15 → 16 行，界面计数一致；新正文匹配 `Sample note [0-9]+` | Counter、Notes、Catalog 的 iOS MCP 重放通过 |
| iPhone 14 / iOS 17.3.1 | 4 → 5 行，界面计数一致 | 6 → 7 行，界面计数一致；新正文匹配 `Sample note [0-9]+` | Counter、Notes、Catalog 的 iOS MCP 重放通过 |

每次数据库前后采集均绑定精确设备、安装的 Bundle ID 和已校验分析索引。iOS 17 的旧索引在 App 容器变化后被正确拒绝，重新分析后才读取当前安装。`sandbox-file` 命令现在自行建立精确设备的临时 SSH 转发，无需另开转发终端。新增的采集、界面和安装案例均通过 `copyapp verify`。原始 SQLite、IPA、截图、签名资料和 SSH 密钥保存在 Git 忽略的本地 `cases/`。

修复后 309 项 Python 测试通过。`copyapp-0.1.2-py3-none-any.whl` 的元数据和命令入口已检查，SHA-256 为 `617fd93e0aa4d348f1a065cb168e4375b2fed938601b287e95e96d01a060aa73`。安装 wheel 不会自动安装手机 tweak、SSH 服务、Frida、Xcode 或签名资料。

首版边界仍在：分享扩展已打包和索引，但未触发用户交互；第三方 App 的加密包试点不代表所有保护方式均支持；陌生 App 零样本自动复刻、整 App 等价、Claude CLI 自主闭环及 iOS 26 尚未验收。此次夹具核验只证明选定的本地流程和抽样的 SQLite 写入语义。
