# Copy APP v0.1.4: fixture share extension opened on iOS 16 and 17

[English](v0.1.4.md) · [简体中文](v0.1.4.zh-CN.md)

This release extends the [v0.1.3 validation](v0.1.3.md) on the same iPhone XR / iOS 16.1.1 / Dopamine rootless and iPhone 14 / iOS 17.3.1 / Relaxin RootHide. The earlier selected-flow analysis, encrypted-package, Frida, independent-clone and SQLite checks retain their recorded scope.

The known-source fixture now has a **Share sample text** button and is version 0.1.1 (build 2). On each phone, a user-facing system text share sheet listed the fixture's share target from its packaged `FixtureShare.appex`; selecting it displayed the extension's own centered label. The exact [two-device record](../fixture-share-extension-two-device.md) includes the successful 12-step XR and 14-step iPhone 14 iOS MCP replays, their verified install cases and screenshots, plus retained failures from initial installation and dynamic share-sheet coordinates. The tracked playbooks provide repeatable, device-specific checks. Counter, Notes and Catalog were rerun against the updated original fixture on both phones; all six regression cases passed `copyapp verify`.

The shared Python suite passed 309 tests for this release. The `copyapp-0.1.4-py3-none-any.whl` metadata and CLI entry point were checked; wheel SHA-256: `7ae6b9260a3d66ecae84c7dbb0ecd5da5dd4b9edc0e80006c5c0c40dd0cf9dea`.

This validates invocation and visible UI for one known-source extension on the two named phones. The extension does not process the shared item. Generic third-party extension behavior, whole-App equivalence, unfamiliar-App autonomous cloning, an autonomous Claude CLI run and iOS 26 remain unverified. On RootHide, the pinned Frida 17.23.3 sidecar remains the verified original-Calculator trace route; the packaged 16.1.4 server still fails on that App.
