# Copy APP v0.1.8：首次使用引导与双机四路 App 检查

[English](v0.1.8.md) · [简体中文](v0.1.8.zh-CN.md)

[双机验证矩阵](../two-device-verification-matrix.zh-CN.md)新增 iPhone XR / iOS 16.1.1 与 iPhone 14 / iOS 17.3.1 上两条原版 App 流程。**同一份已提交 Translate 脚本**在两机的 iOS MCP、iCTRL 上均显示精确合成文字 `copyappfixture`；**同一份已提交 Clock 脚本**在四种组合中均启动并停止非零秒表。八份新 `flow-capture` 案例通过 `copyapp verify`，截图和 UIKit/无障碍文字支持可见结果。iOS 17 Translate 在输入后自动显示结果；未评估其语义质量，也未对照复刻该结果。

XR 旧版 Translate iOS MCP 失败用原点击点 `(207,320)` 再次复现：字符派发返回成功，截图有光标但没有键盘或文字。新共享脚本点击可见输入提示 `(100,201)`，键盘出现并成功输入。这是该界面随聚焦位置变化的交互差异，不能判作整机文本输入失败。旧失败案例保留，没有暗中自动切换后端重试。

iOS 17 首次使用前，Translate 与 Clock 启动请求报错时，SpringBoard 实际显示各自的 **Welcome / Accept & Continue** 页面。在测试手机完成首次使用选择后，两个 App 都进入自身前台进程；重新运行的 `survey --launch` 案例也通过，采集前后前台 Bundle ID 与目标一致。[首次使用说明](../ios17-first-use-gates.zh-CN.md)解释诊断边界，并保留设备所有者对数据选项的决定权。

另从正式发布页下载 v0.1.7 wheel 并在隔离目录加载。新的 v0.1.8 `doctor` 案例 `cases/ios16-v018-doctor-20261017/`、`cases/ios17-v018-doctor-20261017/` 再次确认两机 USB、截图、开发者文件系统、固定主机密钥的 mobile SSH、Frida、iOS MCP 和已配对 iCTRL 可用；四份已保存的分析到复刻父案例再次通过证据校验。这些产物和选定流程检查仍不能证明整 App 等价、陌生 App 自主生成、Clock 后台行为、Translate 全功能、独立 Claude CLI 运行或 iOS 26 支持。

发布验收：**310 项单元测试通过**。八份新流程、保留的旧点击失败对照、两份首次使用后采集案例及两份 v0.1.8 `doctor` 案例均通过 `copyapp verify`。已核对 `copyapp-0.1.8-py3-none-any.whl` 的元数据、命令入口与隔离安装；SHA-256：`cec0b0967d6d01beb781648eb53c811ebae356a9cb199f678eaa320da23f41c5`。
