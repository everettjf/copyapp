# 系统 Notes：iPhone XR 从分析到独立复刻

[English](notes-xr-workflow.md) · 简体中文

本次选定流程实测使用越狱 iPhone XR / iOS 16.1.1 的系统 Notes 2.10（`com.apple.mobilenotes`），完成 Copy APP 的两大阶段：有来源引用的分析报告，以及在同机安装、对照的独立 iOS App。设备证据保存在忽略提交的本地 `cases/notes-copy-ios16-20261017/`；公开源码见 [NotesClone](../rebuild/NotesClone/README.zh-CN.md)。仓库与发布 wheel 不包含私人笔记正文。

## 第一阶段：分析

1. 用 iOS MCP 发现三条本地账户流程：文件夹 → Notes、新建笔记 → 输入合成标题及正文 → 完成、搜索合成标题。
2. 经精确设备 USB/SSH 获取安装包及有边界的 App 容器元数据。包索引有 169 个文件项、7 个 Mach-O；主程序 Objective-C 索引有 336 个类。容器扫描有 49 个路径元数据项，未读取笔记正文或 App Group 记录。
3. 检查加密状态。该系统 Notes 包内二进制没有加密命令，因此分析 IPA 直接使用验证过的未加密原包快照，不启动手机端砸壳助手。本次发现并修复了旧流程在这种包上仍等待助手约 140 秒的问题。
4. 对“新建笔记”和“搜索”的选定入口做运行时计数。新建方法在按钮点击窗口中当前 IMP 与静态偏移各命中一次；搜索更新方法在搜索框获得焦点时命中一次、输入 19 个字符的窗口内命中 19 次；searchQueryDidChange 在输入窗口命中一次。这里只是限定窗口的时间相关证据。
5. 使用 Hopper 6.6.0 对精确二进制中的新建入口与两个搜索函数生成伪代码，支持“创建并展示编辑器”和“构造查询、调用数据源”的路径解释。伪代码不是 Apple 源码，不能推出全部持久化或排序逻辑。本地审阅报告 `cases/notes-copy-ios16-20261017/analysis-agent/reviewed-report/report.md` 分别标出观察、推断和未知项。

## 第二阶段：复刻与对照

独立的 [UIKit 工程](../rebuild/NotesClone)最低支持 iOS 16.0，自己的本地笔记写入 JSON。XR 安装的 IPA SHA-256 为 `4e9d8c53842b2c3f5356498096b5de9302b4533b1d43548f3856642f88fbeee4`，Bundle ID 为 `com.copyapp.notes`。三条原版/复刻版脚本通过，三组截图审阅为轻微差异。本地父案例 `cases/notes-copy-ios16-20261017/` 及报告、安装、对照、视觉审阅和交付案例均通过 `copyapp verify`；Python 回归 322 项通过。

测试中最关键的状态问题是：系统 Notes 在“新启动”后仍可能恢复上次编辑页，而搜索脚本预设能看到 Folders 返回按钮。Agent 明确返回文件夹根页，再把 Notes 正常置于后台保存恢复状态，随后续跑同一案例；操作记录保存在本地案例中。首次出现的“Organize with Tags”引导也在最终截图对照前关闭。今后的脚本要写明起始页面与首次使用状态，不能把新启动等同于清空导航。

剩余差异主要是重复测试在两边分别积累的合成笔记数量、编辑页返回文字、部分工具栏图标以及搜索卡片分组。本次只验证**三条本地流程**的浅到深复刻，不代表完整 Notes。iCloud、富文本、附件、协作、锁定、存储内部结构、服务端行为和 iOS 17 原版 Notes 均未验证。iPhone 14 上有既存私人笔记，因此本次未用它测试系统 Notes。
