# Current-code iOS 17 device replay · 2026-10-18

[English](ios17-current-code-validation.md) · [简体中文](ios17-current-code-validation.zh-CN.md)

The USB-connected iPhone 14 (`iPhone14,7`, iOS 17.3.1, Relaxin/RootHide) was selected by exact UDID `00008110-001650202E81401E`. The current `main` doctor case `cases/ios17-return-current-doctor-20261018` verified USB lockdown and screenshot, DVT listing, the RootHide SSH namespace, authenticated mobile SSH, the configured Frida sidecar, iOS MCP and iCTRL. `cases/ios17-return-current-calculator-analysis-20261018` acquired the installed original Calculator bundle, static indexes and SSH sandbox metadata, with a verified-frontmost iOS MCP screenshot. Both cases passed `copyapp verify`.

The original Calculator and separately signed `dev.copyapp.calculator.ios17fresh` 0.1.1 (2) were replayed through iOS MCP in `cases/ios17-return-current-calculator-four-flow-20261018`. All four selected flows passed their final UIKit text assertions: `7 + 8 = 15`, decimal result `0.3`, negative result `−7`, and percent result `0.5`. All five screenshot pairs were opened and recorded in `cases/ios17-return-current-calculator-visual-review-20261018` as minor typography or system return-label differences. The comparison and review cases passed `copyapp verify`.

An additional original-App `7 + 8 = 15` run in `cases/ios17-return-current-calculator-traced-flow-20261018` attached the RootHide Frida sidecar, bound `_TtC10Calculator15CalculatorModel::buttonPressed:` to the acquired Calculator binary, and recorded one call for each of five taps. Its flow and trace passed `copyapp verify`. This is runtime evidence for that selected sequence, not a complete account of Calculator's implementation.

An extra iCTRL paired replay was attempted after the iOS MCP acceptance. The original flow passed, but the rebuilt flow ended at the equals tap with `ictrl: malformed HTTP response` (`cases/ios17-return-current-calculator-ictrl-20261018`). A separate experiment confirmed that a coordinate tap could change the rebuilt App, but a second paired attempt still ended at equals with the same transport error (`cases/ios17-return-current-calculator-ictrl-coordinate-20261018`). Both failed attempts are retained; a returned tap message and a later visible `15` do not prove that the final iCTRL response completed. A subsequent doctor probe again found the channels available. The experimental coordinate-tap code was reverted because it did not solve the failure. iCTRL's rebuilt-App multi-step reliability remains open.

These cases are ignored local evidence. The verified scope is the named phone, App builds and selected flows; it does not establish whole-App equivalence, arbitrary-App reconstruction, iCTRL reliability or reboot/rejailbreak persistence.
