# Clean-checkout phone provisioning · 2026-10-18

[English](clean-checkout-phone-provisioning.md) · [简体中文](clean-checkout-phone-provisioning.zh-CN.md)

This trial used a new local clone and virtual environment on the **same physical Mac**. It did not use the main checkout's ignored SSH profiles, keys or Frida configuration. Two exact USB devices were present: XR/iOS 16.1.1 Dopamine rootless and iPhone 11/iOS 26.0.1 Relaxin/RootHide. The main checkout's already trusted SSH route was used only to compare each fresh tunnel's host key with the phone's own host public key and to authorize a new temporary `mobile` public key without a phone password. A genuinely new Mac still needs its own USB pairing and first SSH authorization.

| Stage | XR / iOS 16 | iPhone 11 / iOS 26 |
| --- | --- | --- |
| Fresh host | Local clone, `bootstrap-macos.sh` and `--trace`; new virtual environment | Same clone and environment; RootHide host Frida was then pinned to 17.23.3 |
| First `onboard` | Created a new SSH key; analysis correctly reported setup needed | Created a separate new SSH key; analysis correctly reported setup needed |
| SSH trust | New `22416` tunnel host key matched the phone key read through the existing trusted route; new key login returned the exact UDID | Local port `22426` was already an iOS MCP forward, so SSH used `22526`; its host key matched the phone key and new login returned the exact UDID |
| Post-authorization `onboard` | Rebuild host tools and required analysis channels ready; optional DVT file listing still failed, with SSH available | Rebuild host tools ready. Before Frida sidecar configuration, the old CLI incorrectly reported deep analysis ready from a generic USB process inventory. The corrected CLI reports `needs setup` and prints the RootHide repair. After sidecar setup it reports ready. |
| Real App acquisition | Original Clock package, static index, sandbox metadata and UI captured through an `analyze --launch` call without SSH flags | Same original Clock acquisition without SSH flags |
| Runtime and rebuild | iCTRL pairing was not configured in this new clone; no rebuild was installed from the XR side | Official pinned RootHide Frida sidecar configured and verified; a five-second Clock method probe attached and resolved `MTAStopwatchController::_startStopButtonDown:` with zero calls during that idle window. The tracked independent ClockIOS26 source was built in this clone, signed using this Mac's existing development identity and a profile covering the exact device, installed by USB as build 2, then passed a 13-step Start → Stop → Reset iOS MCP playbook. |

All listed doctor, sidecar, acquisition, install and playbook cases passed `copyapp verify` after being copied into ignored local `cases/clean-phone-provision-20261018/`; the short standalone Frida trace is a JSON observation rather than a case verifier input. The final clone screenshot was manually inspected as a visible reset Stopwatch. Both temporary SSH public keys were then removed from the phones, their new-key logins were rejected, and the original trusted logins were rechecked. The new private keys were not copied into the evidence directory. The signed build reused this Mac's existing certificate and provisioning profile, so it does not establish developer account setup or phone signing on another Mac. iCTRL first pairing from the clone and a full reboot/rejailbreak were not tested.

After correcting RootHide readiness, fresh current-code `doctor` cases on both phones passed verification: `cases/ios16-after-clean-onboard-fix-20261018` and `cases/ios26-after-clean-onboard-fix-20261018`. XR still had SSH, Frida and iOS MCP available; iOS 26 reported `usb_roothide_sidecar` as the Frida transport and retained its RootHide marker. The revised onboarding and marker-detection checks are covered by the 341-test local suite.
