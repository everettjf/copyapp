# Copy APP v0.1.14：iOS 16 上直接启动 TrollStore helper

[English](v0.1.14.md) · [简体中文](v0.1.14.zh-CN.md)

此版本调整 iPhone XR 的 TrollStore 安装路径。Copy APP 仍固定 USB 设备、SSH 主机公钥、helper 位置及暂存 IPA 哈希，并只结束经过核验的同一 App 进程；现在改为通过 root Frida 直接启动已安装的 TrollStore helper。安装器检查有效 UID 为 0、等待该 helper 进程退出，再从安装服务核对指定 Bundle ID、版本及构建号。超时会保存停止请求和当时观察到的已安装版本；实际安装命令不会自动重试。`copyapp verify` 同时核验直接进程证据与 IPA 快照，旧 shell 路径的安装案例仍可校验。

此次修改针对 XR 上复现的故障：旧 shell 包装路径在 Podcasts 复刻版 build 2 升级时超时两次、build 4 升级时超时一次，检查时仍是旧版；build 4 的无参数启动探测成功后，真正安装仍卡住。独立直接进程诊断随后装上 build 4。使用此版本的正式直接路径，build 5 和 6 的递增版本升级都首次成功，其中一次是在复刻版前台使用后更新。两次安装均与保存的 IPA 核对。相同源码签名后通过 USB 升级 iPhone 14 / iOS 17.3.1，build 5 和 6 也都首次成功。

build 5 在两机通过保存的资料库、搜索、现在收听复刻版脚本（六份完整且可校验案例）。build 6 在两机启动后，前台 Bundle ID 与 0.1.5（6）版本/构建号均匹配。此前 Podcasts 原版/复刻版交付仍只是**选定导航行为通过且存在重大视觉差异**；这些升级回归不能证明整 App 已复刻。直接 helper 路径不能获取退出码或标准输出，因此成功判定依据 root 身份、进程退出和精确安装包观察。两次正式 XR 升级不能证明长期首次成功率。iOS 26、任意 App、陌生 App 全自主源码生成、独立 Claude CLI 运行、Clock 长时间受干扰计时及完整沙盒/网络解释仍在本版验证范围外。

发布验收：**318 项单测通过**，包括回环 HTTP 夹具。两机 build 6 安装与启动案例、六份 build 5 复刻版脚本均通过 `copyapp verify`。设备证据与签名材料仍留在 Git 忽略的本地 `cases/`；发布包不包含手机 IPA 或私有数据。Wheel SHA-256：`04301af1fedf9f30b0c153d1620b2a2e0d2a74784f5c65c92a8b3bce7606aca1`。
