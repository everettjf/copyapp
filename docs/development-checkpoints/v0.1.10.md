# Copy APP v0.1.10: Clock state and in-use upgrades on both phones

[English](v0.1.10.md) · [简体中文](v0.1.10.zh-CN.md)

The [Clock cross-device record](../clock-clone-two-device.md) now covers an updated independent clone on iPhone XR / iOS 16.1.1 / Dopamine rootless and iPhone 14 / iOS 17.3.1 / Relaxin RootHide. Its Stopwatch state is saved and restored across process relaunch. In separate real-device runs on both phones, the exact stopped value survived a fresh launch, and a running stopwatch remained running and advanced after a forced process restart. The original Clock and clone also passed a same-device stopped-relaunch comparison on each phone. The updated clone passed iCTRL start/stop regression on both phones. These checks cover selected states, not background timing accuracy or all Clock features.

Installation now saves its input IPA inside the local case before transfer. It requests termination of the exact target Bundle ID through an already paired iCTRL runner. On the XR TrollStore path, it also inspects Frida's process path and each candidate's on-device `Info.plist`, then stops only a matching Bundle ID. The iOS 17 USB path has a 120-second asynchronous install timeout. With the prior clone running on both phones, versioned upgrades through **Clock 0.1.3 (4)** completed through TrollStore on XR and development-signed USB on iPhone 14. Build-4 install cases retain their own IPA snapshots and still verify with the mutable build output removed; the clone then relaunched with nonzero stopped state. A direct XR probe verified that the final process cleanup stops the selected App. XR TrollStore timed out twice on identical build 2 and on the first build-4 attempt; InstallationProxy confirmed build 3 remained installed, and a retry from the saved build-4 IPA succeeded. These failures remain local evidence, not passing attempts.

Release QA: **312 unit tests passed**, including installer identity filtering, timeout recording and IPA snapshot survival after source mutation. Seventeen build-2 persistence/UI/comparison cases, four build-3 upgrade/relaunch cases, and four final build-4 upgrade/relaunch cases currently pass `copyapp verify`. The XR build-2 install case referred to a mutable build IPA that was later overwritten; its original bytes are unavailable, so it is not counted. Before the next rebuild, the byte-identical XR build-3 IPA was relocated into its local case with an explicit record note; that case continues to verify. The `copyapp-0.1.10-py3-none-any.whl` version and console entry loaded from an isolated install. Wheel SHA-256: `fae103816af48969e48c2f3ee7deeb73ea2556cb2d5e9e67275d8ec199e7d396`. Local `cases/` evidence is Git-ignored; committed source, playbooks and documentation describe how to rerun the checks.
