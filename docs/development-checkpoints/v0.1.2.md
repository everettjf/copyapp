# Copy APP v0.1.2: verified fixture storage on iOS 16 and 17

[English](v0.1.2.md) · [简体中文](v0.1.2.zh-CN.md)

This release extends the [v0.1.1 two-device validation](v0.1.1.md). Clone the repository, check out `v0.1.2`, and follow the [Mac setup](../../README.md#install-and-run-your-first-survey). It supports the tested **selected-flow** analysis and rebuild path on iPhone XR / iOS 16.1.1 / Dopamine rootless and iPhone 14 / iOS 17.3.1 / Relaxin RootHide. The detailed device services, acquisition, Frida and visual-review gates remain in the prior release notes.

## What the deeper check found

The earlier Notes playbooks asserted that the visible count rose by one. A direct, read-only SQLite comparison found a behavioral difference: the original fixture inserted `Sample note <Unix timestamp>`, while the independent clone inserted only `Sample note`. The old UI and screenshot checks could not detect this. The first clone database captures, `ios16-fixtureclone-notes-before/after-20261017` and `ios17-fixtureclone-notes-before/after-20261017`, preserve this evidence locally.

The clone's `NoteStore` now writes the same timestamped format. It was rebuilt as version 0.1.1 (build 2), installed through TrollStore on XR and with Apple Development signing over USB on iPhone 14. Both install cases passed `copyapp verify`. After the repair, the same-device checks passed:

| Device | Original Notes SQLite/UI | Repaired clone Notes SQLite/UI | Repaired clone UI regression |
| --- | --- | --- | --- |
| XR / iOS 16.1.1 | 14 → 15 rows and matching screen count | 15 → 16 rows and matching screen count; new text matches `Sample note [0-9]+` | Counter, Notes and Catalog passed iOS MCP replay |
| iPhone 14 / iOS 17.3.1 | 4 → 5 rows and matching screen count | 6 → 7 rows and matching screen count; new text matches `Sample note [0-9]+` | Counter, Notes and Catalog passed iOS MCP replay |

Each before/after file is sourced from an exact device, installed Bundle ID and verified analysis index. On iOS 17, an older analysis index was correctly rejected after the App container changed; a fresh analysis bound the subsequent capture to the current installation. The new `sandbox-file` CLI invocation owns an exact-device temporary SSH forward, so a separate tunnel terminal is unnecessary. All new capture, UI and install cases passed `copyapp verify`. Raw SQLite files, IPAs, screenshots, provisioning material and SSH keys remain in ignored local `cases/`.

The 309-test Python suite passed after the repair. The `copyapp-0.1.2-py3-none-any.whl` metadata and CLI entry point were checked; its SHA-256 is `617fd93e0aa4d348f1a065cb168e4375b2fed938601b287e95e96d01a060aa73`. Installing this wheel does not install the phone tweak, SSH server, Frida, Xcode or signing assets.

The first-version boundaries still apply: the share extension was packaged and indexed but its user-facing invocation was not exercised; third-party encrypted-package pilots do not prove every protection strategy; unfamiliar-App zero-shot cloning, whole-App equivalence, Claude CLI autonomy and iOS 26 are unverified. The repaired fixture checks only the selected local flows and the sampled SQLite write semantics.
