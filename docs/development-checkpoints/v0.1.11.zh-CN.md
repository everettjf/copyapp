# Copy APP v0.1.11：保留 TrollStore 超时证据

[English](v0.1.11.md) · [简体中文](v0.1.11.zh-CN.md)

XR 的 TrollStore helper 此前在两次相同构建重装和一次 Clock 递增版本升级中超时。现在 helper 超时不会丢失有界的 root 命令日志：`device-run/output.txt` 与 `device-run/result.json` 记录实际输出、超时状态及是否请求停止 Frida 启动的进程；`install.json` 同时记录超时后 InstallationProxy 返回的目标 Bundle ID 版本/构建号，或记录查询错误。安装器不会自动重试不确定的操作，也不会把“已请求停止”写成“所有子进程已结束”。旧失败案例继续保持失败状态。

XR 上一条无害的 1 秒超时命令先输出 `timeout-control` 再休眠。真机案例 `cases/ios16-root-timeout-diagnostic-retry-v0111-20261017/` 保留了输出，并记录 `status=timed_out`、`exit_code=null`、`process_stop_requested=true`。此前一次使用 `/bin/sh` 的尝试因 rootless shell 实际位于 `/var/jb/bin/sh` 而退出 127，另行保留。单元测试覆盖有界超时日志，以及安装超时后观察到旧版而不自动重试的情况。

独立 Clock 项目升级到 **0.1.4 (5)**，秒表实现没有变化。XR 临时签名 IPA SHA-256 为 `cd403edd08534c1c4049f8320af4bfbc526d7f7c317e92cffee1b12704410ee5`；iPhone 14 开发者签名 IPA 为 `872a603dc411afe72c4b5a4f52619622f8afed76fdf3c54feff49086671ec7b4`。XR TrollStore 与 iOS 17 签名 USB 升级本次都首次通过。两机安装及停止态重启案例均通过 `copyapp verify`，升级前的精确停止值仍在：XR `02:52.80`、iPhone 14 `02:00.94`。这两次成功不足以推断首次安装成功率，也没有消除之前偶发的 helper 卡住问题。

发布验收：**314 项单元测试通过**。iOS MCP 测试需要绑定本地 HTTP 服务；沙盒内首次尝试在服务初始化时失败，允许本地回环访问后完整重跑通过。Wheel 在隔离目录安装，并核对版本和 CLI 入口。Wheel SHA-256：`d4f4aba8b1a5b9db0f076c963013bf275c48f1b2676e88244bde95460c7c117b`。本地 `cases/` 证据不提交 Git；[双机矩阵](../two-device-verification-matrix.zh-CN.md)和[Clock 记录](../clock-clone-two-device.zh-CN.md)说明已测范围及未完成项。
