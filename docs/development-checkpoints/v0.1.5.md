# Copy APP v0.1.5: share-extension plain-text receipt on iOS 16 and 17

[English](v0.1.5.md) · [简体中文](v0.1.5.zh-CN.md)

This release extends the [v0.1.4 two-device share-extension invocation check](v0.1.4.md). The tested phones remain iPhone XR / iOS 16.1.1 / Dopamine rootless and iPhone 14 / iOS 17.3.1 / Relaxin RootHide. The earlier selected-flow analysis, encrypted-package, Frida, independent-clone and SQLite results retain their recorded scopes.

The known-source fixture is now version 0.1.2 (build 3). Its `FixtureShare.appex` loads a text item from the system `NSItemProvider` and displays a bounded preview. On both phones, the exact synthetic host text `Copy APP fixture sample text` appeared in the extension as `Received: Copy APP fixture sample text`. The XR 12-step and iPhone 14 14-step iOS MCP playbooks passed with final UIKit observations and saved screenshots, and both install cases passed `copyapp verify`. Six Counter, Notes and Catalog regressions on this exact fixture build also passed. The [two-device record](../fixture-share-extension-two-device.md) describes the evidence and the retained XR install timeout, which succeeded on retry after stopping the host and extension processes.

The 309-test Python suite passed for this release. The `copyapp-0.1.5-py3-none-any.whl` metadata and CLI entry point were checked; wheel SHA-256: `d5213c1460cac24cb63afd51478f084f7b36c89644df19b6804ec08b872dbe12`.

This proves one synthetic plain-text route through one known-source extension on the two named phones. Other content types, persistence, network effects, unrelated extensions, whole-App equivalence, unfamiliar-App autonomous cloning, an autonomous Claude CLI run and iOS 26 remain unverified. On RootHide, the pinned Frida 17.23.3 sidecar remains the verified original-Calculator trace route; the packaged 16.1.4 server still fails on that App.
