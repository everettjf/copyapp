# Copy APP v0.1.12: standalone acquisition on both tested iOS versions

[English](v0.1.12.md) · [简体中文](v0.1.12.zh-CN.md)

Standalone `copyapp acquire --transport ssh` and `copyapp sandbox` now open and authenticate a short-lived USB SSH forward for the exact `--udid`, pinned host key and selected account. Previously these commands required a separate forward even though `analyze` managed one itself. A connection to the wrong phone remains a hard failure.

On iPhone XR / iOS 16.1.1 Dopamine rootless and iPhone 14 / iOS 17.3.1 Relaxin RootHide, Apple Podcasts completed package/static analysis and bounded sandbox indexing. The verified analysis cases contain respectively 153/152 bundle files and 13/12 indexed binaries. Both main executables have no encryption load command, so Podcasts did not exercise decryption. The standalone acquisition cases also pass `copyapp verify`; standalone `sandbox` writes a JSON index rather than a verification case.

Each phone passed three device-specific `discover-check` paths—Library, Search and Listen Now—with six final screenshots inspected. On iOS 17, the first launch returned an error while SpringBoard displayed Podcasts onboarding. After the welcome page and a WLAN Only wireless-data choice, Podcasts entered its own foreground process and the three checks passed. The XR had a separate Library introduction. These paths validate entry and navigation. A Podcasts semantic code report, independent rebuild, playback, and whole-App equivalence have not been completed. [Two-device matrix](../two-device-verification-matrix.md).

Release QA: **314 unit tests passed** when the local HTTP fixture was allowed to bind loopback; an earlier sandbox-only attempt failed at fixture setup. The wheel loaded as version **0.1.12** from an isolated install directory. Wheel SHA-256: `4d2e90a469fa819ff25f67570f1a8e30c4748a85cdfca00805cacb9110198841`. Local phone cases and private App data remain Git-ignored.
