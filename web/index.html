// 01 — THE WORKFLOW

Two phases. One evidence trail.

Go from observed behavior to a reviewed implementation. Each phase leaves inspectable cases behind.

01UNDERSTAND THE ORIGINAL
⌁

Understand the behavior

Collect iOS package, sandbox and runtime evidence, or macOS package, AX and UI evidence. Review a sourced report and feature specification.

  • Installed app & sandbox
  • UI flows & screenshots
  • iOS runtime / macOS accessibility
  • Reviewed report & feature spec
→
02BUILD AN INDEPENDENT APP
◈

Rebuild selectively

Build a separate iOS or macOS app. Compare the same selected flows, review every screenshot and stop at the reviewed grade target or cycle limit.

  • Capability inventory & target
  • Independent source, IPA or .app
  • Paired behavior & visual checks
  • Verified delivery & known gaps
CORE PRINCIPLE / 001

A passing screenshot is a data point. A trustworthy rebuild is a chain of observations, decisions, and repeatable checks.

See what really happened.

Named device identity, package hashes, bounded actions, screenshots and runtime traces live in local evidence cases.

Trace claims back to proof.

Optional iOS native inspection uses Ghidra or Hopper. macOS UI evidence establishes selected behavior, not deep native function semantics.

Original and rebuilt flows run separately in the same pinned environment. Deliveries name behavior passes, visible differences and unknowns.
