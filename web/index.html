// 01 — THE WORKFLOW

Two phases. One evidence trail.

Go from observed behavior to a reviewed implementation. Each phase leaves inspectable cases behind.

01UNDERSTAND THE ORIGINAL
⌁

Analyze deeply

Collect package, sandbox, UI and runtime evidence. Inspect Mach-O code and selected methods. Write a sourced report and feature specification.

  • Installed app & sandbox
  • UI flows & screenshots
  • Frida traces & native code
  • Reviewed report & feature spec
→
02BUILD AN INDEPENDENT APP
◈

Rebuild selectively

Choose a realistic coverage target. Build and install an independent iOS app. Replay the same flows and review the differences on device.

  • Capability inventory & target
  • New Xcode project & signed IPA
  • Paired behavior & visual checks
  • Verified delivery & known gaps
CORE PRINCIPLE / 001

A passing screenshot is a data point. A trustworthy rebuild is a chain of observations, decisions, and repeatable checks.

01 / COLLECT

See what really happened.

Named device identity, package hashes, bounded actions, screenshots and runtime traces live in local evidence cases.

02 / INTERPRET

Trace claims back to proof.

Native inspection can use bundled tooling, Ghidra or Hopper. Pseudocode is evidence to review, never recovered source code.

03 / VERIFY

Measure only the chosen scope.

Original and rebuilt flows run separately on the same phone. The final delivery names passes, visual differences and unknowns.
